# 기능 이관 명세

## 문서 목적

이 문서는 현재 프로젝트의 기능을 새 스택으로 이전하기 위해 필요한 기능 범위, 화면 구성, 데이터 모델, API 범위, 권한 규칙, 운영 흐름을 정리한 문서다.

이 문서의 초점은 Hugo/PocketBase 구현 세부가 아니라, 실제 서비스 기능을 새 기술 스택에서 다시 만들 수 있도록 기능을 추출하는 데 있다.

---

## 1. 시스템 개요

현재 프로젝트는 다음 3가지를 동시에 수행하는 하이브리드 커머스 사이트다.

1. 공개 쇼핑몰과 블로그를 사용자에게 제공한다.
2. 회원, 장바구니, 주문, 리뷰, 상품 문의를 실시간으로 처리한다.
3. 관리자 화면에서 상품과 게시글을 관리하고, 이를 정적 페이지에 반영한다.

구조적으로는 아래 5개 도메인으로 분해할 수 있다.

1. 공개 사이트
2. 회원/인증
3. 장바구니/주문/결제
4. 리뷰/Q&A
5. 관리자 CMS

## 4. 회원/인증 기능

### 4.1 회원가입

- 입력 항목: 이름, 이메일, 비밀번호, 비밀번호 확인, 닉네임
- 닉네임 중복 검사
- 이메일 중복 검사
- 회원가입 직후 자동 로그인

### 4.2 로그인

- 이메일/비밀번호 로그인
- 이메일 기억하기
- 로그인 실패 메시지 표시

### 4.3 OAuth 로그인

- Google 로그인
- Kakao 로그인
- 로그인 전 현재 URL 저장
- 로그인 성공 후 저장된 URL로 복귀

### 4.4 로그아웃

- 인증 스토어 초기화
- 홈 또는 언어별 메인으로 이동

### 4.5 헤더 상태 반영

- 비로그인 시 로그인/회원가입 링크 노출

- 아바타가 없으면 기본 아이콘 표시

### 4.6 프로필 관리

- 닉네임 변경
- 휴대폰 변경
- 우편번호, 기본주소, 상세주소, 추가주소 변경
- 저장 후 현재 로그인 사용자 정보 갱신

### 4.7 비밀번호 변경

- 현재 비밀번호 입력
- 새 비밀번호 입력
- 새 비밀번호 확인
- 일치 여부 검증 후 변경

## 5. 장바구니 기능

### 5.1 장바구니 구조

- 비회원 장바구니 지원
- 회원 장바구니 지원
- 장바구니 헤더와 장바구니 아이템 분리 구조

### 5.2 장바구니 식별 방식

- 비회원은 `session_id` 기반 장바구니 사용
- 회원은 `user` 기반 장바구니 사용
- 로그인 시 기존 비회원 장바구니를 회원 장바구니에 병합

### 5.3 품목 구분 방식

- 동일 상품이라도 옵션 조합이 다르면 다른 품목으로 취급
- 현재 옵션 필드: 색상, 사이즈
- 메타 정보로 상품 URL, 슬러그 등을 함께 보관

### 5.4 장바구니 상호작용

- 품목 추가
- 품목 수량 증가
- 품목 수량 감소
- 품목 삭제
- 소계/총액 계산
- 품목 총 수량 배지 표시
- 장바구니 드로어 열기/닫기

### 5.5 장바구니 표시 내용

- 상품 이미지
- 상품명
- 옵션 요약
- 수량
- 품목 총액
- 상품 상세 페이지 이동 링크

### 5.6 장바구니 병합 규칙

- 로그인 전 장바구니가 있고 로그인 후 회원 장바구니가 존재하면 병합
- 동일 옵션 조합은 수량 합산
- 서로 다른 옵션 조합은 별도 품목 유지

- 기본 주소
- 상세 주소
- 추가 주소

### 6.2 배송지 편의 기능

- Daum 우편번호 검색 연동

### 6.3 주문 상품 요약

- 장바구니 품목 목록 표시
- 상품명, 수량, 소계 표시
- 총 결제금액 계산

### 6.4 결제 수단

- KG 이니시스
- 카카오페이

- 이메일

### 6.6 결제 전 검증

- 배송지 필수값 검증

- 결제 응답 정보 일부 저장
- 배송지 정보 저장
- 재고 차감
- 장바구니 품목 삭제

### 6.8 주문 데이터에 저장되는 정보

## 12. 다국어 기능

### 12.1 기본 구조

- 기본 언어는 한국어
- 영어 콘텐츠 별도 제공
- URL 구조는 `/ko/...`, `/en/...`

### 12.2 다국어 요소

- 헤더 메뉴 언어 전환
- 로그인/회원가입 일부 문구 번역
- 상품 목록 언어별 필터링
- 통화 포맷 언어별 처리

### 12.3 주의사항

- 일부 프런트 코드에 `/ko/` 하드코딩이 남아 있음
- 새 스택으로 이관 시 라우팅과 링크 생성 로직을 완전히 재정리하는 것이 좋음

## 16. 핵심 비즈니스 규칙

1. 장바구니는 비회원과 회원 모두 사용 가능해야 한다.
2. 로그인 시 기존 비회원 장바구니는 회원 장바구니와 병합되어야 한다.
3. 장바구니 품목은 상품 ID만이 아니라 옵션 조합까지 포함해 구분해야 한다.
4. 상품 비활성화 시 일반 사용자에게는 숨겨야 한다.
5. 리뷰와 문의 작성은 로그인 사용자만 가능하다.
6. 리뷰 수정/삭제는 작성자 본인만 가능해야 한다.
7. 비밀 문의 본문은 작성자와 관리자만 확인할 수 있어야 한다.
8. 주문 취소는 제한된 상태에서만 가능해야 한다.
9. 결제 직전 재고를 다시 검증해야 한다.
10. 주문에는 당시 상품 정보 스냅샷을 저장해야 한다.
11. 운송장 등록 시 배송 상태를 자동 전환하는 규칙이 필요하다.

## 17. 운영 흐름

현재 운영 모델은 CMS 저장만으로 끝나지 않는다.

1. 관리자 화면에서 상품 또는 게시글 수정
2. 동기화 스크립트 실행
3. 정적 사이트 빌드 실행
4. 공개 산출물 갱신

즉 현재 프로젝트는 실시간 서비스와 정적 사이트 배포가 혼합된 구조다.

## 18. 동기화 및 정적 생성 기능

### 18.1 상품 동기화

- 백엔드 상품 데이터를 읽어 로컬 콘텐츠 파일 생성
- 상품 이미지를 내려받아 로컬 에셋으로 저장
- 상품별 Markdown 파일 생성

### 18.2 게시글 동기화

- 백엔드 게시글 데이터를 읽어 로컬 Markdown 파일 생성
- 대표 이미지 다운로드
- DB에서 삭제된 게시글은 로컬 파일도 제거

### 18.3 빌드

- Hugo로 정적 사이트 생성
- 최종 산출물은 `server/` 디렉터리에 배치
